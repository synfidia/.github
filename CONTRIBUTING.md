# Contributing to Synfidia

## Start with the project

Read the target repository README, current status and license before contributing. Repository-specific contribution instructions take precedence over these defaults.

This .github repository maintains the Synfidia organization profile and shared community files. Report project-specific problems in the relevant project repository.

## Report a reproducible problem

- Search existing issues before opening a new one.

- Include the version or commit, relevant environment, steps to reproduce, and expected versus actual behavior.

- Use a small example and redact credentials, personal information and confidential data from logs or screenshots.

## Propose an improvement

Explain the problem, who encounters it, and what a useful outcome would look like. Discuss substantial changes in an issue before implementing them. A suggestion is not a commitment to delivery.

## Submit a pull request

- Keep each pull request focused on one change and explain why it helps.

- Follow the repository setup and verification instructions. Report the checks you ran and any checks you could not run.

- Update related documentation and add regression coverage when behavior changes. For documentation-only changes, check links and rendered formatting.

- Use the existing approved brand assets. Do not add customer claims, performance claims or new licensing terms without supporting review.

## Handle sensitive reports carefully

Do not post secrets or exploitable vulnerability details in public issues. Follow the target repository security policy or private reporting option when available. If no private route is documented, ask how to contact the maintainers without disclosing the sensitive details.

## Work respectfully

Keep discussions specific and constructive. Review the work, explain your reasoning, and give contributors time to respond.
